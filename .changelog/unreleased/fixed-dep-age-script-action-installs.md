- **The release-age workflow guard follows workflow-invoked scripts and local composite actions, and refuses an install it cannot resolve.**

  One scanner judges workflow and action `run:` blocks and followed shell files with the same clause splitting, `cd` state, command substitutions (`$(...)` and backtick spans, each with its own `cd` and nested state), wrapped interpreters and install classifier; the two callers differ only in their initial state, and here-document bodies are install-screened. The guard is a fail-closed lint for reviewed changes: it passes an install only as a bounded global install or when it resolves to a tracked lockfile, and refuses an install or invocation it cannot resolve unless a reviewed allowlist entry names it; it is not a boundary against an author who deliberately evades it. Installs inside followed JavaScript or TypeScript scripts, node inline payloads, and `npm run`/`bun run` targets in `package.json` are not inspected; enforcement is cli#948.
