- **The release-age workflow guard follows workflow-invoked scripts and local composite actions, and refuses what it cannot resolve in the shapes it parses (cli#975).**

  One scanner judges workflow and action `run:` blocks and followed shell files with the same clause splitting, `cd` state, command substitutions (`$(...)` and backtick spans, each with its own `cd` and nested state, with quote state and span nesting lexed in one pass so a quote inside a body cannot hide a later span in that lexer; other passes that track quotes are a known limit, cli#975), wrapped interpreters and script resolution; the two callers differ in their initial state, and the install classifier runs on followed shell files while a run block's lines are screened by the physical-line check, which does not flag `npx`; here-document bodies are install-screened. The guard refuses what it cannot resolve in the shapes it parses; nested quoting inside substitutions is a known limit (cli#975). It passes an install only as a bounded global install or when it resolves to a tracked lockfile, and refuses an install or invocation it cannot resolve unless a reviewed allowlist entry names it; it is not a boundary against an author who deliberately evades it. Installs inside followed JavaScript or TypeScript scripts, node inline payloads, and `npm run`/`bun run` targets in `package.json` are not inspected; enforcement is cli#948. An ANSI-C quote (`$'...'`) is one quote in which a backslash escapes the next character and `$(` and a backtick are literal. A step whose `working-directory` is not a literal relative path starts at an unknown cwd, so a relative invocation or a cwd-bound install on it is unresolved, except a computed token whose literal suffix names an existing repository file; an unresolved-invocation refusal names the step and the invocation path. A clause whose first word is an assignment whose value holds a closed command substitution and that has more words after it is refused: a run block offers computing the value on its own line or adding the step to the exact-block allowlist, and a followed script offers computing the value on its own line or naming the script in a reviewed entry. A `$(` the lexer reads as literal text is not a substitution, so the clause is scanned.
