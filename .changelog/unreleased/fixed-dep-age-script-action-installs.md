- **The release-age workflow guard follows workflow-invoked scripts and local composite actions, and refuses an install it cannot fully resolve.**

  The guard is a fail-closed lint for reviewed changes: it passes an install only as a bounded global install or when it resolves to a tracked lockfile, and refuses anything else; it is not a boundary against an author who deliberately evades it. In followed shell scripts every install clause is judged, an install line whose npm/npx shape cannot be read is refused, and an unknown cwd is sticky until a `cd` to an absolute in-repository, repository-root-anchored or script-directory path. A tracked-lock helper bind, a wrapped interpreter with an absent or non-literal payload, a repeated npm directory flag, a reviewed `source` not derived from its pinned assignment and a reviewed entry pinning an env-overridable default are refused. Installs inside followed JavaScript or TypeScript scripts, node inline payloads, and `npm run`/`bun run` targets in `package.json` are not inspected.
