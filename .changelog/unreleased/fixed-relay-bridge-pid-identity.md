- **Relay and bridge pid files attempt to record the process start token, which a stop checks immediately before signalling; a mismatch is refused.** A pid can still be reused between that check and the signal, and the `ps` fallback compares start time only to the second. The writer reads the token through the agent API, which may return null or a `ps`-derived token. A stale record is removed; a record whose identity cannot be confirmed is refused with the pid file named, and an EPERM from the stop signal keeps the file and exits non-zero. `bridge stop` classifies both known pid files before acting, handles each record independently, prints every record's outcome, and exits non-zero when a stop fails or a record is kept without a verified stop.
