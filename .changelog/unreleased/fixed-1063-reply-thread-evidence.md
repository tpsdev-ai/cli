- **A reply sent with `--reply-to` now settles its obligation on an office host, and the prompt suggests a command that writes where the scan looks.** The prompt's reply command carries `--reply-to <inbound envelope id>` and, when the account config sets a `mailDir`, a shell-quoted `TPS_MAIL_DIR=<mailDir>`. A signed-mode obligation accepts a committed reply that signs that id even without an obligation marker; a record carrying an `X-TPS-Nack` marker is never evidence. A reply with no, a different, or an unverifiable signed thread still does not settle. Branch-host replies are relayed through the outbox, where this marker-less form is not enabled, so they are not matched by this change; neither is a reply sent through the channel send tool during the turn: the runtime does not supply the inbound's signed envelope id as `ctx.replyToId`, so it is not covered.
