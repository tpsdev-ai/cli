- **A reply sent with `--reply-to` now settles its obligation on an office host when the inbound sender's route is local.** There the prompt suggests `tps mail send <to> --reply-to <inbound envelope id>`, with a shell-quoted `TPS_MAIL_DIR=<mailDir>` when the account config sets one, so the reply lands where the scan reads. A signed reply that signs that id settles without an obligation marker; a record carrying `X-TPS-Nack` never settles. Branch hosts and remote/bridge routes are not matched by this change. A configured `mailDir` that is not absolute after `~` expansion is refused at plugin config load.
