- **A launch that adds a worktree marks it, so a failure after the add removes that worktree.** Immediately after the add, setup writes a random nonce to the worktree's admin git directory with exclusive create, reports the worktree path and nonce to the caller, then reads its identity facts. The setup-failure cleanup re-reads the nonce before removing the worktree; if the nonce or a recorded identity fact no longer matches, it refuses, names the path and prints the manual `git -C <base> worktree remove --force <path>` command. A worktree swapped in between that check and the removal is not covered; the verify-to-remove race is deferred. The worktree is added detached, so no branch is created or removed.
