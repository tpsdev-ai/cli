- **A launch that creates a worktree attempts to write an ownership marker, and cleanup attempts to remove that worktree only while the marker still matches.** Immediately after `git worktree add`, setup attempts to write a random nonce to the worktree's admin git directory with exclusive create, reports the record to the caller, then reads its identity facts. A marker it cannot write is a setup failure: the record has no marker and cleanup refuses, naming the path and printing a POSIX-quoted `git -C <base> worktree remove --force <path>` command. When a later setup step fails, cleanup attempts to remove the worktree it created if the marker and any recorded identity facts still match, and otherwise refuses with that command; the removal itself can fail. The setup-failure cleanup, the launch fallback and the `onStop` teardown route attempt removal of a created worktree only when the admin directory holds the exact recorded nonce; teardown does not compare HEAD, which the runtime may move. A worktree swapped in between that check and the removal is not covered; the verify-to-remove race is deferred (cli#678). The worktree is added detached, so no branch is created or removed.
