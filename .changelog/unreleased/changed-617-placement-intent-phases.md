- **Mail placement intents carry a phase; MailClient recovery, the CLI lease sweep and promotion skip or preserve non-`placing` intents (Refs #617).** Phase names here are the phase `phaseOf` resolves. It checks `version`, `presentations` and `firstPresentedAt` before `phase`, and an unsupported value in any of them resolves to `unknown` whatever `phase` says: `version: 2` with no `phase`, and `version: 2` with `phase: "failed"`, both resolve to `unknown`. An intent with no `phase`, a recognized `version` (absent or `1`) and valid liveness values (`presentations` a non-negative safe integer, `firstPresentedAt` a parseable timestamp, each optional) resolves to `placing`. So an otherwise-valid older intent whose `file` is a plain basename is handled exactly as before, records with no intent are handled as before. On those paths, a record whose intent resolves to `in_progress` or `unknown` (an unsupported value in the recognized `phase`, `version`, `presentations` or `firstPresentedAt` fields; other extra fields are ignored) is never finished, replaced, presented or checked out. Such an intent is not quarantined solely for that value, and it keeps only its own file's delivery gate closed. An intent that resolves to `failed` leaves its per-file (filename) gate open, while its message ID stays refused by the consumed-ID (replay) gate; it is not presented on those paths. It stays until an operator removes it, and its payload follows ordinary `cur/` archive and GC retention. One exception to preserving a non-`placing` intent: once a `failed` payload has left `cur/`, a different message may reuse the name. Its placement moves the marker to `.placement-<hash>.failed-<messageId>.json`, which keeps the old consumed ID retained, if that tombstone name is unoccupied or is the marker's own inode (treated as an interrupted move). An occupied tombstone refuses the reuse by name and keeps both files, and the new message is not delivered. While the payload is still in `cur/`, the new message waits.

  A placement intent whose `file` is not a plain basename (empty, `.`, `..`, or containing `/`, `\` or NUL) is now refused on write and quarantined on read. That includes an older intent the previous parser accepted when its hashed name matched: the one exception to legacy parity.
