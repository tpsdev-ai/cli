- **The `packages/agent` maildir→model path fails CLOSED: verification is mandatory and a verifier throw is no longer a pass (Refs #380).** `MailClient.checkNewMail()` — the mailbox behind `AgentRuntime`'s tool-holding EventLoop, a fourth consumer alongside the three runtimes moved onto the shared promote() lifecycle — guarded verification behind `if (this.flairClient)`, so a runtime built without Flair config promoted `new/`→`cur/` unverified; and `verifyMailBody()` swallowed a verifier throw and returned `pass: true`, so a Flair outage promoted unverified mail straight into the model. A record now reaches `cur/` ONLY after its signed envelope verifies: no verifier → the record is left untouched in `new/` (refuse, do not promote — non-destructive, so a later check with a verifier promotes it), a throwing verifier → the record is left in `new/` for a later check (a transient outage self-heals), and a deterministic rejection → dead-lettered to `dlq/`. The reject sidecar is now the shared `.reason` file with a leading `class:` line — an unresolvable principal is labelled `unresolvable-principal` rather than `invalid`, matching the shared promotion boundary — instead of the `.reject` file no shared reader scans.
