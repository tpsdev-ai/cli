- **The task loop and `tps agent logs` read Flair's catch-up envelope rather than a list (Closes #624).** A `task.assigned` event now reaches the task handler, the loop resumes from the feed position it persisted, and `FlairClient.getEventsSince` returns the read's outcome, so a caller can tell an empty feed from an unreadable one.

  A refused or failed request, a malformed page (including an event whose `id` or `targetIds` is malformed), an unreadable signing key and an invalid `since` are each reported as unavailable with a bounded reason, so `tps agent logs` says the OrgEvents are unavailable and still shows mail. When a task handler throws, the loop stops at that event and retries it, in the same process or after a restart, before any later event; the persisted position never passes it. Delivery is at least once, not exactly once: a crash after a handler returns and before the position is written replays that event on restart, so handlers must be idempotent.

  The cursor file (`~/.tps/cursors/<agent>-task-loop.json`) is now written atomically and holds `{ position, updatedAt }`. A legacy `{ since }` file still resumes from its timestamp, `tps office status` shows the cursor's timestamp in either format, and an unreadable cursor file is logged and treated as no cursor (the first read then looks back one hour).
