- Pin the Docker image's nono install to the immutable commit behind tag v0.74.0 (`commit=` in `.nono-version`, verified via `git rev-parse HEAD`), replacing the unpinned default-branch clone (cli#341).
- **Contract the image is now built to satisfy:** the shipped `nono` bytes come only from the pinned `nono-builder` commit. `nono-builder` records the sha256 of the binary it built at the asserted commit; the runtime stage copies that hash in and its **last instruction** re-hashes `/usr/local/bin/nono` and fails the *build* if the two differ — and the recorded hash cannot be rewritten within the stage, so the comparison cannot be made vacuous. The assertion calls its tools by absolute path (`/usr/bin/sha256sum`, `/usr/bin/cut`, `/bin/cat`) and the stage sets no `ENV PATH`, so a PATH shadow cannot substitute them. Capability removal is best-effort hardening; this assertion is the control (cli#341).
- The runtime stage installs only what the shipped workload needs: `git` (the agents it starts shell out to git), `ca-certificates` (TLS for git), `jq` (the supervisor uses it), `libdbus-1-3` and `node`. No `curl`, `wget`, `python3`, `nc`, `socat` or `php` is installed (cli#341).
