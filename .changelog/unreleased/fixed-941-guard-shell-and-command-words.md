- **The workflow npm guard reads `shell:` and restricts command-word shapes.** Step `shell:` overrides job defaults, which override workflow defaults; a non-`bash` shell refuses an unapproved run block, naming its source line. The guard refuses leading redirections and variable assignments containing `<` or `>` before a command word in unapproved run blocks. Command words containing `*`, `?`, `[` or `$'` are refused, except `[` and `[[` themselves. Command-position `time`, `coproc`, `function`, `in` and `]]` are refused in unapproved run blocks; `!` is skipped before the assignment search. `case` in command position is refused in unapproved run blocks. In unapproved run blocks, an unclassified here-document header, delimiter or body boundary refuses the step, naming the physical line. Modelled headers are single-line top-level simple-command `<<`/`<<-` redirections with bare, single-quoted or double-quoted `[A-Za-z_][A-Za-z0-9_]*` delimiters, queued in source order. Unquoted bodies join backslash-newline before delimiter comparison; quoted bodies compare literally; `<<-` strips leading tabs. Literal brackets in `${...}` defaults do not hide a following header; nested expansions stay opaque. The command-word, redirection, assignment and `case` checks read a run block's top-level clauses only: commands inside `$(...)` or backtick substitutions, and text after a quote that spans physical lines, are not checked. This best-effort lint does not model compound commands; variable or substitution indirection and composite-action shells are not covered.
