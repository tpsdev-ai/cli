- **The workflow npm guard reads `shell:` and restricts command-word shapes.** Step `shell:` overrides job defaults, which override workflow defaults; a non-`bash` shell refuses an unapproved run block, naming its source line. The guard refuses leading redirections and variable assignments containing `<` or `>` before a command word in unapproved run blocks. Command words containing `*`, `?`, `[` or `$'` are refused, except `[` and `[[` themselves; `case` in command position is refused in unapproved run blocks. In unapproved run blocks, a here-document header match inside quotes or `$((...))`, or matching a `<<<` here-string, is refused. These checks read a run block's top-level clauses only: commands inside `$(...)` or backtick substitutions, and text after a quote that spans physical lines, are not checked. This best-effort lint does not model compound commands; variable or substitution indirection and composite-action shells are not covered.
