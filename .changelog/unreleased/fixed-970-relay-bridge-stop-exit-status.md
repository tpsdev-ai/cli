- **Breaking: `tps mail relay stop` and `tps bridge stop` refuse a record they cannot verify instead of removing it.** An invalid record at the first read exits non-zero and is kept; a stale record at the first read, whose recorded process is gone, is removed (byte-compared first), and the stop exits 0 unless that removal fails. On the re-read, a missing, invalid, unreadable, unverifiable, or different-pid record exits non-zero; a stale re-read for the verified pid exits 0 only when that process is gone, and both commands then leave the record in place. Before every removal in the stop path each command compares the record's bytes and keeps a record that no longer matches; the compare and the unlink are separate steps, so a record written between them can still be removed.

  **Upgrade:** a script that treated these stops as successful now sees a non-zero exit when the first read finds an invalid record or the re-read refuses as described above. A stop whose re-read matches the verified record, and whose process then exits, still exits 0.
