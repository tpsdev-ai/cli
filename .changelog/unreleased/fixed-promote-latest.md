- **The `latest` promote is now a recorded, checked step (`scripts/promote-latest.sh`), not a note in a run summary (cli#366).** After a tag push, `release.yml` stage-publishes six packages under the `staged` dist-tag and a maintainer approves them in npm — but approval cannot move `latest` (`--tag` is immutable on a staged package and `npm stage approve` has no tag flag), so `npm install` keeps serving the previous version until someone runs `npm dist-tag add`, by hand, per package. A forgotten promote is indistinguishable from a failed release: the version is public, `npm install` serves the old one, and nothing says why.
  The new script performs that step. It verifies BEFORE acting that all six packages exist at the target version, and refuses — naming each missing package — if any does not, because `packages/cli` pins the four platform packages at exact versions and a partial promote would publish a `latest` CLI whose pinned dependencies do not resolve. It shows the current `latest` for each package and what it will do, then requires an explicit `yes` (`--dry-run` stops before any change; `--yes` skips the prompt for a scripted run). It then runs `npm dist-tag add` per package and RE-READS the registry (`npm view <pkg> dist-tags.latest`) to confirm each tag actually moved, rather than trusting the command's exit code — a promote that "succeeded" without moving `latest` is the bug this fixes. If a move fails or does not land, the packages already moved are rolled back to their previous `latest`, so the end state is all six or none. A final table reports package, previous `latest`, new `latest`, and whether each move was verified against the registry.
  `scripts/test-promote-latest.sh` pins the refusals and the registry re-read against a fake registry — no network, no real dist-tag is moved — and includes mutation checks that break the existence check and the post-move re-read and confirm the fixtures catch each. It runs in CI.
  This automates only the promote step that exists today; a canary-gated, sha-bound promote is the remaining half of cli#366.
