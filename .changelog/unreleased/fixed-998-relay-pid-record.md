- **`tps mail relay start` refuses an invalid relay pid record and claims the record path exclusively.** The claim is written completely to a same-directory temporary file and published with a no-replace hard link, so a partial record is never published; cleanup of the temporary file is attempted in a finally block. An invalid record is kept and the start exits non-zero naming the path and the remedy; a stale daemon record is replaced. A later start keeps an abandoned start claim and refuses with a manual resolution step. `relay status` reports whether the start claim names a process with a matching start token; `relay stop` requires unchanged record bytes under the record lock before signalling. The start attempts to hand the claim to its child within one lock budget shared across retries, and reports a retained claim if that fails. The daemon writes its record through a temporary file in the same directory and a rename, and on SIGTERM or SIGINT tries to remove it when the file still holds its own bytes, compared under the record lock.
